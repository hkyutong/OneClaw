# OneClaw use cases

OneClaw is most valuable when you think about it as an **always-on self-hosted AI operator**, not just a CLI or chatbot.

## Best-fit use cases

### Personal AI assistant from chat

You want to message one assistant from the apps you already use.

- send tasks from Telegram, WhatsApp, or other channels
- let the gateway run continuously
- keep your data and workflows under your control

Start here: [Personal assistant](/use-cases/personal-assistant)

### Telegram as the front door

You already live in Telegram and want it to become your main assistant entry point.

- direct-message style assistant workflow
- easy phone plus desktop reachability
- strong fit for an always-on self-hosted gateway

Start here: [Telegram personal assistant](/use-cases/telegram-personal-assistant)

### Founder operator workflow

You want one AI system that helps across product, docs, outreach, research, and operations.

- draft product copy
- help with engineering tasks
- summarize information
- keep a persistent workspace and memory

Start here: [Founder operator](/use-cases/founder-operator)

### Mac primary, Linux server

You want the easiest pattern for serious daily use:

- run the always-on gateway on Linux
- use Mac locally for browser, app, or installer-first setup work
- keep the assistant reachable from anywhere

### Windows with WSL2

You want OneClaw on Windows, but via the practical route:

- WSL2 + Ubuntu
- Docker Desktop
- terminal-based setup

Start here: [OneClaw on Windows with WSL2](/install/oneclaw-on-wsl2)

### Remote always-on assistant

You want your assistant available when your laptop is closed.

- host the gateway on a VPS or home server
- use chat apps and the web UI as remote control surfaces
- keep the runtime under your own control

Start here: [Always-on VPS assistant](/use-cases/always-on-vps)
