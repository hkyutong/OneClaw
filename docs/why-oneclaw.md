# Why OneClaw

OneClaw exists for one reason:

> make a self-hosted AI assistant easier to adopt, easier to explain, and easier to use in the real world.

OpenClaw already provides the core runtime.
OneClaw focuses on the product layer around it.

## Why people choose OneClaw

### 1. Simpler entry point

Many users do not want to start from a framework mental model.
They want a clear answer to:

- what this is
- how to install it
- whether it works on their OS
- what to do first after install

OneClaw tries to answer those directly.

### 2. Better first-run experience

OneClaw puts more attention on:

- macOS-first installer flow
- guided onboarding
- clearer deployment paths
- fewer "read the whole repo first" assumptions

### 3. Better fit for a personal assistant product

OneClaw is opinionated toward the use case most people actually want:

- one always-on assistant
- reachable from chat apps
- self-hosted on your machine or server
- practical enough to use every day

### 4. Chinese-first product copy

OneClaw is designed to lower friction for Chinese-speaking users who want a more direct onboarding and configuration experience.

## Why not just use upstream OpenClaw

You should use upstream OpenClaw if you want:

- the broadest upstream docs
- the most direct view of runtime evolution
- the least opinionated reference project

You should use OneClaw if you want:

- a clearer product story
- easier onboarding
- the macOS installer path
- simpler guidance for Linux and WSL deployment

## Who OneClaw is best for

- solo developers
- founder-operators
- self-hosted AI enthusiasts
- people who want to message an assistant from Telegram, WhatsApp, Discord, or other channels
- people who want a practical AI assistant, not just another CLI

## Who should probably not start with OneClaw

- users who want a fully hosted no-setup SaaS
- users who do not want to manage keys, local runtime, or deployment
- users who only want the raw upstream reference project and no productized layer

## What you actually get

- a self-hosted AI gateway
- multi-channel messaging access
- web UI and local control surfaces
- a macOS-first installer direction
- a Linux and WSL path that still stays practical
